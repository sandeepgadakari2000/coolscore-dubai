# Model card: CoolScore surrogate

| | |
|---|---|
| **What it predicts** | A Dubai apartment's tenant-paid cooling cost (AED): annual, August (summer peak) and January (winter low), each as P10/P50/P90 |
| **Type** | scikit-learn `HistGradientBoostingRegressor`, quantile loss on log(1 + AED), one model per target × quantile × input set (18 models), monotonic in size (+) and AC setpoint (−) |
| **Training data** | 40,000 **simulated** unit-years (seed 42): ISO 13790 hourly physics on 2023–25 corrected Dubai weather → Dubai billing. Not real bills |
| **Split** | 70 % train, 10 % conformal calibration, 20 % held-out test (random, seed 42) |
| **Artifact** | `data/demo/coolscore_model.pkl.xz` (≈ 7 MB) + `model_metrics.json` |
| **Rebuild** | `python tasks.py simulate` (~4 min) then `python tasks.py train` (~2 min) |

## Inputs

- **Listing facts:** weather site (from community), building era, size, bedrooms, floor, total floors, floor fraction,
  top floor, facing (1 or 2 facades), glass amount, balcony, view/obstruction, cooling system, who pays.
- **Optional household details** (a second model variant): household size, home in the daytime, AC setpoint.
- **Hidden (never inputs, so they form the range):** glazing U/SHGC within era limits, wall/roof U, infiltration,
  thermal mass, blinds, absorptance, albedo, unit depth, floor height, fresh-air pre-treatment, appliance gains,
  AC away-mode, window opening, Ramadan schedule, weather year, contracted-capacity allocation, AC efficiency, fan
  power, other household kWh.

## Performance on held-out simulated units

| Inputs | Target | R² | MAE (AED) | MAPE (bills > AED 500) | P10–P90 coverage | Median range width |
|---|---|---|---|---|---|---|
| Listing only | Annual | 0.938 | 793 | 17.3 % | 80.2 % | AED 2,087 |
| Listing only | August | 0.940 | 87 | 12.8 % | 79.6 % | AED 226 |
| Listing only | January | 0.902 | 58 | 17.5 % | 80.3 % | AED 149 |
| + household | Annual | 0.949 | 717 | 15.5 % | 80.0 % | AED 1,873 |
| + household | August | 0.948 | 82 | 12.0 % | 79.0 % | AED 212 |
| + household | January | 0.919 | 50 | 16.0 % | 79.6 % | AED 120 |

**Fidelity** (same algorithm given *all* inputs, including hidden ones, vs held-out physics): R² **0.996** for annual
cost, **0.992** for annual cooling energy (target ≥ 0.95, met). The surrogate reproduces the physics. The gap to the
listing-only R² is genuine uncertainty that no listing can remove; it is shown as the range.

**Calibration:** raw quantile models covered ~75 % of held-out cases. Conformalised quantile regression (Romano et
al., 2019) widens P10/P90 by a log-space margin learned on the calibration split, bringing coverage to 79–80 %.

## CoolScore A–E

Standardised cost intensity (AED per sq ft per year) of the unit under a reference household (bedrooms + 1 people,
out by day, 24 °C), district cooling with tenant-paid tariff, P50. Cut-offs at the 20/40/60/80th percentiles of the
simulated stock: **A ≤ 6.84 < B ≤ 7.36 < C ≤ 7.88 < D ≤ 8.47 < E** (AED/sq ft/yr). The score rates the unit, not the
contract: chiller-free or a cooler thermostat changes the AED shown, not the grade. The stock mix is a design choice,
not Dubai's measured stock, so bands are relative to the simulated mix.

## Intended use and limits

- For comparing units and setting expectations **before** signing; not a quote, bill forecast or audit.
- Valid for apartments in the listed Dubai communities, 250–6,000 sq ft, the four cooling systems modelled.
- Not validated against real bills yet (`docs/validation_report.md` updates automatically as bills arrive).
- Biggest unvalidated assumptions: contracted capacity per sq ft, fresh-air pre-treatment, infiltration, household
  behaviour. All are labelled in `config/assumptions.yaml`.
- Explanations generated by Claude (optional) never add numbers: a guard rejects any number not in the engine output.

## Ethics and data

No personal data in training (fully simulated). Real bills: anonymised typed figures only, explicit consent, PII
test on every run, no bill images. No scraping of property portals.
